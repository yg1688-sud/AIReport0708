# Feature Specification: Excel 数据分析报告自动生成

**Feature Branch**: `001-excel-analysis-report`

**Created**: 2026-07-08 | **Updated**: 2026-07-09

**Status**: Draft

**Input**: User description: "构建一个应用，该应用需要实现自动生成结构化的数据分析报告。生成的报告要保存成模版，客户下次使用时选择已有模版直接生成。具体操作如下：用户登录系统，打开应用页面，上传Excel。未有模版或未选择模版时，通过聊天对话方式确认需求直至点击'确认需求'按钮；选择已有模版时，不可聊天，点击'立即生成报告'直接生成。报告生成后提示用户命名并保存模版。历史报告支持下载和打印。"

## Clarifications

### Session 2026-07-10

- Q: 聊天智能追问由什么驱动？ → A: 混合模式 — 规则引擎引导基础维度/指标选择，自由文本输入时调用 LLM 理解意图并转为结构化参数。
- Q: 用户账户如何创建？ → A: 管理员预创建 — 无公开注册入口，由管理员在后台创建用户账户并分发凭据。
- Q: 是否需要历史报告管理功能？ → A: V1 包含完整历史管理 — 历史列表 + 搜索 + 按日期筛选 + 手动删除 + 批量下载。
- Q: 上传的原始数据文件保留多久？ → A: 与报告同期保留 7 天，用户可在有效期内基于原始数据"重新生成"报告，过期自动清理。
- Q: 单次上传文件数量上限？ → A: 最多 20 个文件。
- Q: 是否需要分析模版功能？ → A: 是。报告生成后保存为模版；下次可选择已有模版直接生成，跳过聊天对话。
- Q: 模版是否支持编辑？ → A: 不支持编辑（仅覆盖）。模版保存后不可修改参数；用户可通过重新生成报告并覆盖同名模版实现参数更新。
- Q: 多文件策略与模版模式冲突时如何处理？ → A: 检测冲突并提示。模版策略与当前策略不一致时提示用户，确认后自动切换策略。
- Q: 模版保留多久？ → A: 永久保留。模版仅存储分析参数元数据，无过期时间，仅用户手动删除时移除。

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 用户登录与身份验证 (Priority: P1)

用户打开应用，通过账号密码登录系统，获得访问权限后才能使用数据分析和报告生成功能。

**Why this priority**: 登录是所有后续操作的前置条件。根据宪法安全原则，所有 API 端点 MUST 要求身份验证，未登录用户不得访问任何功能。

**Independent Test**: 未登录用户访问任何功能页面时被重定向至登录页；使用有效凭据登录后成功进入主页面并看到上传入口。

**Acceptance Scenarios**:

1. **Given** 用户未登录, **When** 访问应用任意页面, **Then** 系统重定向至登录页面。
2. **Given** 用户在登录页面, **When** 输入正确的用户名和密码并提交, **Then** 系统验证通过并跳转至应用主页。
3. **Given** 用户在登录页面, **When** 输入错误的用户名或密码并提交, **Then** 系统显示"用户名或密码错误"提示，不跳转。
4. **Given** 用户已登录, **When** 长时间未操作导致会话过期（2小时）, **Then** 下次操作时系统提示"会话已过期，请重新登录"并跳转至登录页。

---

### User Story 2 — 多文件上传与校验 (Priority: P1)

用户登录后，在应用页面上传数据文件（支持 .xlsx、.csv 格式），可一次上传多个文件。上传区域以列表形式展示所有已上传文件，每个文件独立显示上传/解析进度，并提供删除按钮和"清空所有"按钮。所有文件解析完成后系统提示"所有文件就绪"。

**Why this priority**: 文件上传是数据分析的数据入口，没有数据则后续所有功能无法运作。

**Independent Test**: 上传一个合法文件，系统展示上传进度并完成解析，列表中显示文件名、大小和状态；上传多个文件，每个文件独立显示进度；所有文件解析完成后显示"所有文件就绪"提示。

**Acceptance Scenarios**:

1. **Given** 用户已登录且位于主页面, **When** 选择一个或多个合法数据文件（.xlsx/.csv）上传, **Then** 上传区域以列表形式展示每个文件的名称、大小、上传/解析进度（百分比或进度条）。
2. **Given** 某个文件正在上传或解析中, **When** 用户点击该文件项旁的删除按钮, **Then** 该文件从列表中移除，上传/解析任务取消。
3. **Given** 上传列表中已有文件, **When** 用户点击"清空所有"按钮, **Then** 系统弹出二次确认对话框"确定要清空所有文件吗？"，用户确认后所有文件从列表中移除。
4. **Given** 文件大小 >5MB, **When** 系统开始解析该文件, **Then** 该文件项显示加载动画或进度提示，告知用户解析进行中。
5. **Given** 多个文件同时上传, **When** 系统并行解析所有文件, **Then** UI 展示整体解析进度（如"3/5 个文件已就绪"）以及每个文件的独立状态。
6. **Given** 所有已上传的文件均解析完成, **When** 最后一个文件解析成功, **Then** 系统显示"所有文件就绪"整体提示。
7. **Given** 用户上传文件, **When** 单个文件大小超过 100MB, **Then** 系统提示"单个文件大小不能超过 100MB"，拒绝该文件。
8. **Given** 用户上传文件, **When** 所有文件总大小超过 500MB, **Then** 系统提示"文件总大小超过 500MB，建议分批上传"。
9. **Given** 用户上传非支持格式的文件, **When** 文件格式不是 .xlsx/.csv, **Then** 系统提示"仅支持 .xlsx 和 .csv 格式文件"，拒绝该文件。

### User Story 3 — 多文件处理策略 (Priority: P2)

系统统一使用"分别分析"策略（每个文件独立出报告），用户无需手动选择。单文件可走对话模式或模版模式；多文件时必须选择已有模版，不支持对话模式。

**Why this priority**: 简化用户操作路径，多文件场景通过模版保证一致性。

**Independent Test**: 上传 1 个文件后可进入对话模式或选择模版；上传 2 个文件后必须选择模版，对话模式不可用。

**Acceptance Scenarios**:

1. **Given** 用户上传了多个文件且全部解析就绪, **When** 系统检测到文件数量 >1, **Then** 系统展示模版选择区域，不提供"不使用模版"选项，提示"多文件必选模版"。
2. **Given** 用户上传了多个文件但无可用模版, **When** 文件就绪, **Then** 系统提示"需要选择分析模版才能生成报告"，阻止进入对话模式。
3. **Given** 用户仅上传了一个文件且文件就绪, **When** 系统展示模版选择区域, **Then** 提供"不使用模版（进入对话模式）"选项。
4. **Given** 用户仅上传了一个文件且无模版, **When** 文件就绪, **Then** 系统直接进入对话模式。

---

### User Story 4 — 分析模版选择 (Priority: P2)

文件就绪后，若用户已有保存的分析模版，系统展示模版选择区域。单文件时可选模版或对话模式；多文件时必须选模版。

**Why this priority**: 模版是提高重复分析效率的核心机制，直接影响用户操作路径。

**Independent Test**: 有历史模版的用户，单文件时看到模版列表+对话选项；多文件时仅看到模版列表。

**Acceptance Scenarios**:

1. **Given** 用户有已保存的模版且文件就绪, **When** 页面加载模版选择区域, **Then** 以列表或下拉形式展示所有可用模版（显示模版名称和保存时间）；单文件时提供"不使用模版"选项，多文件时不提供。
2. **Given** 多文件场景且用户选择了模版, **When** 点击"立即生成报告"按钮, **Then** 每个文件独立生成一份报告。
3. **Given** 用户选择了模版, **When** 模版中引用的分析列在当前上传文件中不存在, **Then** 系统提示"模版 [模版名称] 中的列 [列名] 在当前数据中不存在，请重新选择"，阻止直接生成。
4. **Given** 用户无任何已保存模版且单文件, **When** 文件就绪, **Then** 系统直接进入聊天对话模式。

### User Story 5 — 聊天式需求确认 (Priority: P2)

**前置条件**：用户未选择分析模版。系统启动聊天对话界面，以问答方式引导用户明确数据分析需求（如：选择分析维度、指标、图表类型等）。全部对话记录在聊天区域可见，支持滚动查看历史。用户可输入"确认"或点击"确认需求"按钮结束对话，系统锁定需求并开始生成报告。

**Why this priority**: 需求确认是报告生成的质量保证环节。当无模版可用时，聊天交互是唯一的需求输入方式。

**Independent Test**: 未选择模版后进入聊天界面，系统自动发送第一条引导消息；用户发送分析需求后系统智能追问；聊天区域可滚动查看全部历史消息；输入"确认"后系统在 1 秒内返回 Task ID。

**Acceptance Scenarios**:

1. **Given** 用户未选择模版, **When** 系统进入聊天模式, **Then** 系统主动发送第一条引导消息（如："我已读取您的数据，请告诉我您希望进行哪些分析？例如：销售趋势、分类汇总、对比分析等"）。
2. **Given** 聊天对话进行中, **When** 用户输入模糊的分析需求（如"帮我分析一下销售情况"）, **Then** 系统追问具体维度（如"您希望按地区、时间还是产品类别来分析销售？"）。
3. **Given** 聊天对话中已有较多消息, **When** 用户向上滚动, **Then** 可查看全部历史对话记录，不丢失任何消息。
4. **Given** 聊天对话进行中, **When** 用户输入"确认"或点击"确认需求"按钮, **Then** 系统在 1 秒内返回任务回执（Task ID），显示"需求已确认，正在生成报告..."并跳转至报告生成等待页面。
5. **Given** 聊天对话进行中, **When** 用户输入的需求引用了数据中不存在的列名, **Then** 系统提示"您的数据中未包含'{列名}'字段，请从以下可用列中选择：{可用列列表}"。
6. **Given** 聊天对话进行中, **When** 用户连续快速发送多条消息, **Then** 系统按序接收并逐一回复，不丢失消息、不卡死界面。
7. **Given** LLM 确认需求, **When** 确认文本中包含 `<!--PARAMS group=... sum=... -->` 机器标记, **Then** 系统优先解析标记中的结构化参数驱动计算，跳过正则检测；标记缺失时自动回退正则/语义兜底。

### User Story 6 — 自动生成结构化数据分析报告 (Priority: P2)

需求确认（对话模式）或点击"立即生成报告"（模版模式）后，系统自动执行数据分析并生成结构化报告。报告包含：数据概览、描述性统计、汇总指标、图表可视化（柱状图/折线图/饼图/漏斗图/条形图）、计算结果表格等章节。支持导出 Excel（含表格数据和汇总指标）、下载 PDF、浏览器打印。对于常规数据（≤10,000 行），30 秒内完成；对于大型数据（>10,000 行），3 分钟内完成并展示实时进度。对话模式下报告生成后，系统提示用户命名并保存模版。时间统一使用本地 24 小时制。

**Why this priority**: 报告生成是核心价值交付。模版模式和对话模式共享同一生成流程，仅入口不同。

**Independent Test**: 模版模式下点击"立即生成报告"，对话模式下确认需求，均能在限定时间内生成完整报告并展示。对话模式生成后弹出模版保存提示。

**Acceptance Scenarios**:

1. **Given** 需求已确认或模版已选择且数据为常规规模（≤10,000 行、≤50 列）, **When** 系统开始生成报告, **Then** 30 秒内完成并展示完整报告（含数据概览、统计表格、图表）。
2. **Given** 需求已确认或模版已选择且数据为大型规模（>10,000 行）, **When** 系统开始生成报告, **Then** 3 分钟内完成，期间每 ≤2 秒更新进度条并显示当前阶段（如"正在清洗数据..."、"正在计算交叉表..."、"正在渲染图表..."）。
3. **Given** 报告生成完成, **When** 用户查看报告, **Then** 报告包含以下结构化章节：数据概览（行数、列数、缺失值情况）、描述性统计（均值、中位数、最值、标准差）、汇总指标（仅在需求明确要求时展示）、分析图表（按需求生成，支持柱状图/折线图/饼图/条形图由 Chart.js 渲染，漏斗图为纯 SVG；横轴标签从需求中"横轴为XX"动态解析；支持"前N名"Top N 限制）、计算结果表格（支持动态列数）、交叉分析结果（按需求生成）。
4. **Given** 分别分析模式且需求已确认/模版已选择, **When** 系统生成报告, **Then** 为每个文件独立生成一份报告，用户可在报告列表中切换查看各文件的报告。
5. **Given** 报告生成过程中, **When** 发生服务端错误（如数据处理异常）, **Then** 系统友好提示"报告生成遇到问题：[具体原因]，请稍后重试"，并提供重新生成按钮。
6. **Given** 对话模式下报告生成完成, **When** 报告展示后, **Then** 系统弹出模版保存提示："报告已生成，是否将当前分析需求保存为模版？"，提供命名输入框和"保存模版"/"暂不保存"按钮。
7. **Given** 用户在模版保存提示中输入模版名称并点击"保存模版", **When** 模版名称未与已有模版重复, **Then** 系统保存当前分析需求（含维度、指标、图表类型、筛选条件）为模版，提示"模版保存成功"。
8. **Given** 用户输入的模版名称与已有模版重复, **When** 点击"保存模版", **Then** 系统提示"模版名称已存在，是否覆盖？"，用户确认后覆盖旧模版。

### User Story 7 — 报告下载与打印 (Priority: P3)

报告生成完成后，用户可将报告下载为 PDF 文件（支持断点续传）、导出为 Excel 文件（.xlsx 格式，含表格数据和汇总指标），或直接通过浏览器打印功能打印报告。

**Why this priority**: 下载、导出和打印是报告的消费方式，在报告能正常生成后才有价值，属于完善体验的增强功能。

**Independent Test**: 报告生成完成后，点击"下载 PDF"按钮成功下载 PDF 文件；点击"导出 Excel"按钮成功下载 .xlsx 文件；点击"打印报告"按钮触发浏览器打印对话框。

**Acceptance Scenarios**:

1. **Given** 报告已生成, **When** 用户点击"下载 PDF"按钮, **Then** 系统生成 PDF 文件并提供下载，支持断点续传（Range Requests），单次连接 ≤ 60 秒。
2. **Given** 报告已生成, **When** 用户点击"导出 Excel"按钮, **Then** 系统生成 .xlsx 文件（使用 SheetJS，纯前端），含计算结果表格及上方汇总指标，自动下载。
3. **Given** 报告已生成, **When** 用户点击"打印报告"按钮, **Then** 系统触发浏览器打印对话框，报告以适合打印的排版展示（A4 纸张适配）。
4. **Given** 用户下载 PDF, **When** 下载连接超过 60 秒, **Then** 连接自动断开，用户可重新发起下载（从断点续传）。

### User Story 8 — 历史报告管理 (Priority: P3)

报告生成完成后，用户可在"历史报告"页面查看、搜索、筛选和管理所有历史报告，支持查看详情、手动删除和批量下载，报告在 7 天后自动清理。

**Why this priority**: 历史管理是完整的报告生命周期闭环，让用户可回溯过往分析结果，属于增强体验功能。

**Independent Test**: 用户生成多份报告后，进入"历史报告"页面，可看到按时间倒序排列的报告列表，支持关键词搜索和日期筛选，可删除和批量下载。

**Acceptance Scenarios**:

1. **Given** 用户已登录且有历史报告, **When** 进入"历史报告"页面, **Then** 以列表形式展示所有历史报告（按生成时间倒序），每条包含：文件名、生成时间、报告类型（合并/单文件）、文件大小、状态。
2. **Given** 用户在历史报告页面, **When** 在搜索框输入关键词（如文件名）, **Then** 列表实时过滤显示匹配的报告。
3. **Given** 用户在历史报告页面, **When** 选择日期范围筛选, **Then** 列表仅显示该时间范围内的报告。
4. **Given** 用户在历史报告页面, **When** 点击某条报告, **Then** 跳转至该报告的完整查看页面（含下载和打印按钮）。
5. **Given** 用户在历史报告页面, **When** 点击某条报告的删除按钮并确认, **Then** 该报告及其 PDF 文件从服务器永久删除。
6. **Given** 用户在历史报告页面勾选了多份报告, **When** 点击"批量下载", **Then** 系统将选中的报告打包为 ZIP 文件并提供下载。
7. **Given** 某份报告已超过 7 天, **When** 系统执行定时清理, **Then** 该报告及关联文件自动删除，历史列表中不再显示。

### Edge Cases

#### 文件上传边界

- 用户上传空文件（0 行数据）：单独提示该文件"无数据"，并允许用户移除该文件；若所有文件均为空，则提示"所有文件无数据，请上传包含有效数据的文件。"
- 用户上传只有一列数据的文件：系统正常处理，但提示"数据仅包含一列，部分分析类型可能受限"。
- 用户上传包含合并单元格的文件：系统自动展开合并单元格，按展开后的数据参与分析。
- 用户上传的文件列头包含特殊字符或非 UTF-8 编码：系统自动检测编码并转换，无法转换时提示用户。

#### 文件解析错误

- 单个文件解析失败（加密、损坏等）：提示"文件 [文件名] 解析失败，请确认未损坏且未加密。"，并允许用户移除或重新上传该文件。
- 所有列均为空或完全缺失（合并后）：提示"无法生成报告：所有数据列均为空或完全缺失，请检查文件内容。"，并提供重新上传按钮。
- 未能识别任何有效可分析列：合并分析模式下提示"未检测到可分析的数据列，请确认数据格式规范。"；分别分析模式下对每个文件分别检查，跳过无效文件并提示用户。

#### 数据规模限制

- 合并后总行数超过 100 万行或总列数超过 200 列：提示"数据规模过大（合并后超过 100 万行或 200 列），请缩减数据后重试。"，单个文件超出同样限制时标记为不可用。
- 单文件超过 100MB：系统拒绝该文件并提示"单个文件大小不能超过 100MB"。

#### 多文件策略

- 合并分析模式下文件列结构不一致：提示具体差异列（如"文件 A 包含列 [销售额, 利润]，文件 B 缺少列 [利润]"），并建议用户选择"分别分析"模式或调整文件。

#### 分析模版

- 用户选择模版但模版中引用的列在当前文件中不存在：提示具体缺失列名，阻止直接生成，引导用户选择其他模版或切换到对话模式。
- 用户无任何已保存模版：模版选择区域不展示，直接进入对话模式。
- 用户保存模版时输入空名称：提示"模版名称不能为空"。
- 模版保存失败（服务端错误）：提示"模版保存失败，请稍后重试"，不影响已生成报告的查看和下载。

#### 会话与系统

- 用户在聊天环节长时间不操作（>30 分钟）：会话超时，系统提示"会话已超时，请重新上传文件开始"，释放会话资源。
- 用户在报告生成过程中关闭浏览器：任务在服务端继续执行，用户重新登录后可查看历史报告或继续等待当前任务。
- 同时多个用户上传大文件并生成报告：系统保持各用户任务独立，互不影响，总并发不超过 100 个分析任务。
- 用户报告生成完成后刷新页面：报告仍然可见（报告保留 7 天）。
- 前端渲染异常（全局错误边界）：捕获未预期的渲染异常，显示友好错误界面："页面遇到了意外错误，请刷新页面重试。"，并提供"重新上传"入口。

#### 错误信息展示

- 所有错误信息显示在报告区域原位置（或对应文件项旁），并附带"重试"或"重新上传"操作按钮。

## Requirements *(mandatory)*

### Functional Requirements

#### 认证与安全

- **FR-001**: 系统 MUST 要求用户登录后才能访问任何功能页面；未登录用户 MUST 被重定向至登录页。
- **FR-002**: 系统 MUST 支持用户通过用户名和密码进行身份验证；账户由管理员在后台预创建，无公开注册入口。
- **FR-003**: 所有用户输入 MUST 经过服务器端验证，所有 API 端点 MUST 要求身份验证。
- **FR-042**: 系统 MUST 提供管理员功能，支持创建、禁用、删除用户账户；管理员账户通过初始化脚本预置，不可自助注册。

#### 文件上传

- **FR-004**: 系统 MUST 支持上传 .xlsx、.xls、.csv 格式的数据文件，支持一次选择多个文件，单次上传最多 20 个文件；超出时提示"单次最多上传 20 个文件，请分批上传"。
- **FR-005**: 单个文件大小 MUST ≤ 100MB；所有文件总大小 MUST ≤ 500MB（超出时提示分批上传但不强制拒绝）。
- **FR-006**: 上传区域 MUST 以列表形式展示每个文件的名称、大小、上传/解析进度（百分比或进度条）。
- **FR-007**: 每个文件项 MUST 提供独立的删除按钮，点击后取消该文件的上传/解析并移除。
- **FR-008**: 上传区域 MUST 提供"清空所有"按钮，点击后弹出二次确认对话框，用户确认后清除全部文件。
- **FR-009**: 每个文件 MUST 独立显示上传进度（百分比或进度条）；文件大小 >5MB 时解析过程中 MUST 显示加载动画或进度提示。
- **FR-010**: 多个文件并行解析时，UI MUST 同时展示整体进度（如"3/5 个文件已就绪"）与每个文件的独立状态。
- **FR-011**: 所有文件解析完成后，系统 MUST 显示"所有文件就绪"整体提示。

#### 文件校验

- **FR-012**: 系统 MUST 在文件上传后校验文件格式（.xlsx/.csv）、列头完整性和文件大小。
- **FR-013**: 单个文件校验失败时，系统 MUST 返回具体错误原因（格式不符、大小超限、加密/损坏、空文件等）。
- **FR-014**: 校验通过后，系统 MUST 展示数据预览（前 100 行；若文件少于 100 行则展示全部行）。

#### 多文件处理策略

- **FR-015**: 当上传文件数 >1 且全部解析就绪时，系统 MUST 主动询问用户选择处理策略："合并分析"或"分别分析"。
- **FR-016**: 用户选择"合并分析"时，系统 MUST 检查所有文件的列结构一致性（列名和顺序）。
- **FR-017**: 列结构不一致时，系统 MUST 提示具体差异列，并建议用户调整为"分别分析"模式或调整文件。
- **FR-018**: 用户选择"分别分析"时，系统 MUST 确认将为每个文件独立生成报告。

#### 分析模版

- **FR-050**: 文件就绪后，若用户有已保存的模版，系统 MUST 展示模版选择区域（列表或下拉形式），显示模版名称和保存时间。
- **FR-051**: 用户选择模版后，系统 MUST 隐藏聊天对话区域和"确认需求"按钮，显示"立即生成报告"按钮。
- **FR-057**: 选择模版时，若模版保存的处理策略（合并/分别）与用户当前选择不一致，系统 MUST 提示"此模版原用于[合并/分别]分析，与当前选择不同。是否切换为[合并/分别]分析？"，用户确认后自动切换策略；用户拒绝则取消模版选择。
- **FR-052**: 用户选择模版后，系统 MUST 校验模版中引用的分析列是否存在于当前上传文件中；若列不存在则提示具体差异并阻止直接生成。
- **FR-053**: 对话模式下报告生成完成后，系统 MUST 提示用户"是否将当前分析需求保存为模版？"，提供命名输入框和"保存模版"/"暂不保存"按钮。具体规则如下：
  - (a) 保存的模版 MUST 包含：模版名称、分析维度、指标、图表类型、筛选条件、保存时间、关联的列名列表；
  - (b) 若名称与已有模版重复，系统 MUST 提示"模版名称已存在，是否覆盖？"，用户确认后覆盖；
  - (c) 模版名称不可为空，MUST 在 1-100 字符之间。
- **FR-056**: 系统 MUST 提供模版管理入口（在历史报告页面或独立设置页），支持查看已保存模版列表（含模版名称、保存时间、关联列名）和删除模版（需二次确认）。模版保存后不可编辑参数；用户可通过重新生成报告并覆盖同名模版实现参数更新。

#### 聊天交互

- **FR-019**: 用户未选择模版时，文件就绪后（多文件场景则完成策略选择后），系统 MUST 自动启动聊天对话，发送第一条引导消息。
- **FR-020**: 聊天系统 MUST 采用混合模式确认需求：(a) 规则引擎根据 Excel 列的数据类型（数值型→均值/求和/趋势分析；文本型→频次分布/分类汇总；日期型→时间趋势/同比环比）自动提供分析维度、指标、图表类型的选择建议；(b) 用户自由文本输入时调用 LLM 理解意图并转为结构化分析参数，随后追问缺失的维度。
- **FR-021**: 聊天模式下，系统 MUST 显示"确认需求"按钮并识别用户输入的"确认"关键词；模版模式下，"确认需求"按钮 MUST 隐藏。
- **FR-022**: 全部对话记录 MUST 在聊天区域可见，支持滚动查看历史消息。
- **FR-023**: 需求确认（对话模式）或点击"立即生成报告"（模版模式）后，系统 MUST 在 1 秒内返回任务回执（Task ID）。

#### 报告生成

- **FR-024**: 需求确认（对话模式）或点击"立即生成报告"（模版模式）后，系统 MUST 自动开始生成结构化数据分析报告。模版模式下，系统使用模版中保存的分析参数直接生成，无需重新解析需求。
- **FR-025**: 报告 MUST 包含以下结构化章节：数据概览、描述性统计、图表可视化、交叉分析。各章节的具体内容和图表类型由用户通过聊天对话确认的需求决定（即"按需求定制"），该需求参数随后保存为分析模版以供复用。
- **FR-026**: 常规数据（≤10,000 行、≤50 列）的报告 MUST 在 30 秒内完成生成。
- **FR-027**: 大型数据（>10,000 行）的报告 MUST 在 3 分钟内完成生成，并展示实时进度（轮询间隔 ≤ 2 秒）。
- **FR-028**: 进度信息 MUST 包含当前处理阶段描述（如"正在清洗数据..."、"正在计算交叉表..."、"正在渲染图表..."）。
- **FR-029**: 报告生成完成后，用户 MUST 能在页面上查看完整报告。
- **FR-030**: 分别分析模式下，系统 MUST 为每个文件独立生成报告，用户可在报告列表中切换查看。

#### 报告下载与打印

- **FR-031**: 系统 MUST 支持将报告导出为 PDF 文件并下载。
- **FR-032**: 下载接口 MUST 支持断点续传（Range Requests），单次连接 ≤ 60 秒。
- **FR-033**: 系统 MUST 支持浏览器打印功能，打印排版适配 A4 纸张。

#### 错误处理

- **FR-034**: 空文件（0 行数据）：系统 MUST 单独提示该文件"无数据"并允许移除；所有文件均为空时提示"所有文件无数据，请上传包含有效数据的文件。"
- **FR-035**: 全缺失列（合并后所有列为空或完全缺失）：系统 MUST 提示"无法生成报告：所有数据列均为空或完全缺失，请检查文件内容。"
- **FR-036**: 单个文件解析失败（加密/损坏）：系统 MUST 提示"文件 [文件名] 解析失败，请确认未损坏且未加密。"，并允许移除或重新上传。
- **FR-037**: 规模超限（合并后 >100 万行或 >200 列）：系统 MUST 提示"数据规模过大（合并后超过 100 万行或 200 列），请缩减数据后重试。"，单个文件超出同样标记为不可用。
- **FR-038**: 无可分析列：合并模式下 MUST 提示"未检测到可分析的数据列，请确认数据格式规范。"；分别分析模式下对每个文件分别检查并跳过无效文件。
- **FR-039**: 所有错误信息 MUST 显示在原位置（文件项旁或报告区域），并附带"重试"或"重新上传"操作按钮。
- **FR-040**: 应用 MUST 具备全局错误边界，捕获前端渲染异常并显示友好界面，允许用户刷新页面或重新上传。

#### 历史报告管理

- **FR-043**: 系统 MUST 提供"历史报告"页面，以列表形式展示用户的所有历史报告（按生成时间倒序），每条显示文件名、生成时间、报告类型、文件大小、状态。
- **FR-044**: 历史报告列表 MUST 支持关键词搜索（按文件名匹配）和日期范围筛选。
- **FR-045**: 用户 MUST 能点击历史报告条目查看完整报告详情（含下载和打印）。
- **FR-046**: 用户 MUST 能手动删除历史报告（需二次确认），删除后报告及 PDF 文件永久移除。
- **FR-047**: 系统 MUST 支持批量下载选中的多份报告，打包为 ZIP 文件并提供下载。
- **FR-048**: 系统 MUST 在报告创建满 7 天后自动清理报告、关联 PDF 及原始上传文件（同步过期）。

#### 响应式设计

- **FR-041**: 页面 MUST 适配桌面端（1920×1080）和平板端（768×1024）屏幕，采用响应式布局。

### Key Entities

- **用户（User）**: 系统的使用者，由管理员预创建，通过用户名和密码登录。分为普通用户和管理员两种角色。核心属性：用户名、加密密码、角色（普通用户/管理员）、账户状态（启用/禁用）、创建时间、最近登录时间。
- **上传文件（UploadedFile）**: 用户上传的单个数据文件。核心属性：文件名、文件大小、文件格式（.xlsx/.csv）、行数、列数、列头列表、上传时间、解析状态（上传中/解析中/已就绪/解析失败）、错误信息。
- **上传批次（UploadBatch）**: 一次上传操作中的所有文件集合。核心属性：文件列表、总文件数、就绪文件数、总大小、整体状态（上传中/部分就绪/全部就绪）、处理策略（合并/分别/未选择）。
- **分析会话（AnalysisSession）**: 一次完整的需求确认对话过程。关联一个上传批次，包含多条对话消息。核心属性：会话状态（对话中/已确认/已过期/已超时）、处理策略、创建时间、确认时间。
- **对话消息（ChatMessage）**: 聊天中的单条消息。核心属性：发送方（用户/系统）、消息内容、时间戳、关联会话。
- **分析需求（AnalysisRequirement）**: 从对话中提取并确认的结构化需求。核心属性：分析维度列表、指标列表、图表类型、筛选条件、确认时间。
- **分析报告（AnalysisReport）**: 最终生成的结构化报告。核心属性：生成状态（生成中/已完成/失败）、关联文件、各章节内容、创建时间、完成时间、文件大小、报告类型（合并报告/单文件报告）、生成模式（模版模式/对话模式）、关联的分析会话。
- **分析模版（AnalysisTemplate）**: 保存的分析需求模版。核心属性：模版名称、分析维度列表、指标列表、图表类型、筛选条件、关联列名列表、处理策略（合并/分别）、保存时间、关联用户。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从打开登录页到进入主页面完成登录，耗时不超过 30 秒。
- **SC-002**: 用户上传单个 ≤5MB 的文件后，5 秒内完成解析并看到数据预览。
- **SC-003**: 用户上传 5 个文件（每个 ≤10MB），所有文件在 30 秒内完成解析并显示"所有文件就绪"。
- **SC-004**: 用户与系统完成需求对话（≥3 轮问答）后输入"确认"，1 秒内收到任务回执并看到进度页面。
- **SC-005**: 90% 的常规数据（≤10,000 行、≤50 列）在 30 秒内完成报告生成并展示。
- **SC-006**: 100% 的大型数据（>10,000 行）在生成报告期间提供实时进度反馈，进度更新间隔 ≤ 2 秒。
- **SC-007**: 用户从点击下载到获取完整 PDF 报告文件，首次成功率 ≥ 95%。
- **SC-008**: 用户无需操作手册，能在 5 分钟内独立完成"登录 → 上传多文件 → 选择策略 → 确认需求 → 查看报告"的完整流程。
- **SC-009**: 页面在桌面端（1920×1080）和平板端（768×1024）分辨率下均可正常使用，无布局错乱、内容遮挡或横向滚动条。
- **SC-010**: 100% 的文件级错误（解析失败、空文件、格式不符）均显示具体错误信息并附带可操作按钮（移除/重试/重新上传）。

## Assumptions

- 目标用户具备基础的办公软件操作能力，理解数据文件的基本概念（列头、行数据）。
- 用户使用的主流浏览器（Chrome、Edge、Firefox 最近两个大版本）均支持该应用。
- 数据文件的第一行为列头，数据从第二行开始（.csv 文件同样遵循此约定）。
- .csv 文件使用 UTF-8 或 GBK 编码，系统自动检测并转换。
- 数据分析类型默认包括：描述性统计（均值、中位数、最值、标准差、计数）、频次分布、交叉表分析、趋势图/柱状图/饼图等常用图表。
- 用户登录会话有效期为 2 小时，超时后需重新登录。
- 聊天会话超时时间为 30 分钟，超时后需重新上传文件开始。
- 报告 PDF 文件在服务器端保留 7 天，过期自动清理。
- 系统同一时间处理的分析任务不超过 100 个并发请求为合理设计目标。
- 单个文件 ≤100MB 为用户明确指定的限制，超过宪法规定的 20MB 校验窗口的文件将采用异步解析模式，上传响应与校验解耦。
- 文件总大小 500MB 为建议性上限（提示分批），非强制硬限制。
- "合并分析"要求所有文件具有相同的列名和列顺序；列名比较忽略大小写和首尾空格。
- 聊天混合模式中，LLM 调用使用 DeepSeek V4 API（用户指定模型），需处理服务不可用时的降级策略（回退至纯规则引擎模式）。
- 分析模版与用户账户关联，不同用户之间的模版相互隔离，不可共享。
- 模版中保存的是分析需求参数（维度/指标/图表类型等），而非原始数据；使用模版时需重新上传数据文件。
- 模版保存后不可编辑；更新模版的唯一路径是：使用该模版生成报告 → 在对话模式中调整需求 → 确认生成 → 保存时覆盖同名模版。
- 模版永久保留，不限数量，仅用户手动删除时移除。管理员删除用户时，该用户的模版同步删除。
